## 구현

- 수집 → D1/R2 적재 → D1 전용 MCP 엔트리를 단계별 커밋으로 분리했다.
- Actions는 매시간 목록·첨부 메타를 확인하고 최대 3개를 병렬 처리한다. 변경분을 적재하고, 주간 SHA 검사를 수행한다.
- 원본 셀·병합·헤더·각주·전결기호를 보존한다. 검색용 FTS5 2글자 토큰과 정규화 원문 위치 매핑을 수집 시 만든다.
- D1 문서 완료 표식과 검증된 카탈로그 포인터를 사용한다. 부분 적재는 재시도 시 이어가고, 게시 충돌·미완성 문서는 기존 카탈로그를 변경하지 않는다.
- 검색 엔트리 번들에서 ALIO 클라이언트/HWP·PDF 파서가 제외됐음을 자동 확인했다. 기본 5건·offset·scope를 지원한다.

- 기존 corpus/offline 단위 회귀

## 남은 배포 차단 항목

- 현재 CLI는 Cloudflare에 인증되지 않았다. 실제 D1/R2 생성, 제한된 쓰기 자격증명/Secrets 구성, 원격 마이그레이션·최초 213개 적재가 필요하다.
- 운영 CPU·메모리 수치는 확인하지 못했다. JS 경과시간을 CPU 시간으로 취급하지 않았다.
- 원격 D1 REST/R2 서명 업로드·계정 전체 무료 한도, 장기 보관/미사용 버전 정리 정책은 운영 검증이 필요하다.
- 과거 PDF는 기본 제외이며 include_history 요청 시 아직 사전 적재되지 않은 상태를 명시한다.
- 운영 전환은 별도 promotion 설정/커밋으로만 진행한다. 기존 production wrangler 설정과 OAuth KV, 기존 KV 본문 색인은 보존한다.
- 최신 CI 결과는 PR에서 확인해야 한다. 최초 D1 CI는 통과했고 이후 보완 커밋은 별도 검증 대상이다.

## 추가 검증·제한 장치

- 보관된 213개 원본(HWP 119, PDF 94)의 D1 레코드 생성이 모두 통과했다. 조문·별표 등 8,056개, 표 행 31,886개, 산출 JSON 145,522,637 bytes. 이는 전체 DB 적재/FTS 저장 용량이나 최신 ALIO 검증 결과가 아니다.
- 합성 HWPX의 원본 병합 셀 row/col/rowSpan/colSpan이 D1 적재 후 보존되는지 별도 시험했다.
- R2 inventory에는 중단된 업로드도 포함하며, 프로젝트 버킷 1GB 상한을 적용했다. 기존 키 덮어쓰기와 동시 PUT 예약을 모의 HTTP로 검증했다. 실제 R2 인증/서명 요청 성공을 확인한 것은 아니다.
- D1 임대 잠금은 정기/수동 동기화의 중복 실행을 막고 갱신된다. 게시 시에도 소유자·만료를 검증한다. 게시 포인터 충돌은 별도 시험했다.
- 최초 적재 쓰기량은 인덱스/FTS 비용을 포함한다. 샘플·장애 시험에서 약6,400행의 쓰기가 관측됐으며, 전체 실제 적재는 하루 예산에 따라 여러 실행/날짜로 나뉠 수 있다. 이미 완료한 문서와 부분 행은 재사용한다.

마지막 로컬 반복 측정에서는 9개 OAuth MCP 도구의 p95가 모두 약14ms 이내였다. 실제 운영 CPU 10ms 제한 준수 여부는 이 수치로 판단하지 않는다. D1 일별 쓰기 예산은 UTC 날짜별 사용 기록으로 계산하며, R2/REST 모의시험은 실제 인증 시험과 구분한다.
